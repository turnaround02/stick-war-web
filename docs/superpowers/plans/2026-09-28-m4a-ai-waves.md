# M4a 两层 AI 与波次 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让敌方真的会「造兵、推进、撤退」，并让脚本波次真的会出怪。全部在 `src/sim/` 内完成，因此**每一项都能 headless 客观验收** —— 没有一处依赖肉眼。

**Architecture:** 战术层放进 `commandsSystem`（第 2 步）的**开头**，产出与玩家**完全相同的 `Command`**，交给同一步骤后半段消费。这是 spec §9.1 的原意：`commands` = 战术层（「现在造什么兵、要不要推进」），`ai` = 单位层（「找到最近的敌人并打」）。因此**不新增任何 `World` 字段**，六步顺序不变，哈希不新增漏检点。

**Tech Stack:** TypeScript ^5.7.2 / Vitest ^3 / npm

**Spec:** `docs/superpowers/specs/2026-09-25-stick-war-web-design.md`（§8.4 关卡与波次、§9.1 两层 AI、§9.3 harness、§11 M4、§13.6 M4 决策记录）

## Global Constraints

以下逐字取自 spec，**每个任务都隐含包含本节**。

- 逻辑帧率固定 **30 Hz**；所有计时器为**整数 tick**
- 数据表用**秒**书写，经 `toTicks()` 转换**一次**后使用（`data/unitTicks.ts` 是唯一转换点）
- `src/sim/**` **禁止** import `phaser`、`render/`、`input/`、`i18n/`
- sim 内**禁止** `Math.random()`、`Date.now()`、`performance.now()`；随机性只用 `sim/rng.ts`
- **tick 六步顺序不可换**：经济 → 指令 → AI → 运动 → 战斗 → 清理
- 排序比较器**必须是全序**（同值时用 `unit.id` 决胜）
- 代码标识符与注释用**英文**；UI 文案用中文走 i18n 键
- **M3 的 467 个测试是安全网**：任何变红说明改动越界
- **新增 `World` 字段必须同步进 `hashWorld`**（本计划刻意不新增字段）

```ts
/**
 * Whether the enemy still has units due to arrive.
 *
 * A scripted level's enemy force lives ENTIRELY in its wave table, so at t=0
 * the enemy legitimately has zero units on the field. Treating that as
 * annihilation declared the player the winner on tick 1 and the level was over

 * waves, which is exactly right: endless can only be lost, never won by

function enemyHasUnitsPending(world: World): boolean {
  if (world.endless) return true;
```

创建 `src/sim/waves.ts`：

```ts
/**
 * Scripted wave spawning (spec §8.4).
 *
 * A scripted level's enemy has no economy: its whole force arrives through this
 * table. That is a deliberate design for the tutorial level — it moves the
 * player's attention from "manage the economy" to "manage the line" without
 * costing an AI.
 *
 * Waves spawn on ADVANCE. The spec's level-1 table reads as a mounting attack
 * (two swordsmen at 5s, a mixed group at 50s, more at 110s), so `advance` is
 * the only posture that matches its description. A per-wave stance field would
 * be a knob with no user.
 */

import { findSpawnX } from './training';
import { spawnUnit } from './spawn';
import type { Stance, World } from './types';

/** Posture for wave units. See the file comment for why it is not configurable. */
export const WAVE_STANCE: Stance = 'advance';

/**
 * Spawns the next wave if it is due. At most ONE wave per call, so a long
 * frame at 4x cannot collapse two waves onto the same tick — which would
 * double the enemy's local density and change the fight.
 */
export function advanceWaves(world: World): void {
  if (world.waveIndex >= world.waves.length) return;

  const wave = world.waves[world.waveIndex];
  if (world.tick < wave.atTick) return;

  for (const typeId of wave.units) {
    // findSpawnX walks outward from the enemy base front until it finds a clear
    // spot, so a wave never buries a unit inside an existing one.
    const x = findSpawnX(world, 'enemy', typeId);
    world.units.push(
      spawnUnit({ id: world.nextUnitId++, side: 'enemy', typeId, x, stance: WAVE_STANCE }),
    );
  }

  world.waveIndex += 1;
}
```

```ts
/**
 * A tactical AI's tunable knobs (spec §9.1).
 *
 * The spec's difficulty lever is "the decision frequency and how greedy the
 * script is", not a smarter algorithm — so a profile IS the difficulty. Two
 * profiles ship: the enemy's, and a "reference player" used to prove a level is
 * winnable without a human.
 */

import type { UnitTypeId } from '../data/units';

export interface AiProfile {
  /** Ticks between tactical decisions. 30 = once a second. */
  decisionIntervalTicks: number;
  /** How many miners to keep alive before spending on combat units. */
  minerTarget: number;
  /**
   * Combat units in the order they are bought, cycled through. A list rather
   * than weights: it makes the composition deterministic and readable, and
   * "ratio" falls out of the cycle length.
   */
  buildOrder: UnitTypeId[];
  /** Advance when own combat units >= enemy * this. */
  advanceRatio: number;
  /** Retreat when own combat units <= enemy * this. */
  retreatRatio: number;
}

/**
 * The enemy's standard profile.
 *
 * Deliberately slower than the reference player: spec §8.4 wants level 2 to be
 * winnable, and the difficulty knob is decision frequency.
 */
export const ENEMY_STANDARD: AiProfile = {
  decisionIntervalTicks: 45,
  minerTarget: 3,
  buildOrder: ['swordsman', 'archer', 'swordsman', 'spearman'],
  advanceRatio: 1.0,
  retreatRatio: 0.4,
};

/**
 * The reference player — an AI that plays the player's side well enough to beat
 * level 2. Used by tests to assert a level is WINNABLE without a human, which is
 * what turns "can win level 2" from a subjective claim into a deterministic one.
 */
export const PLAYER_REFERENCE: AiProfile = {
  decisionIntervalTicks: 30,
  minerTarget: 4,
  buildOrder: ['swordsman', 'archer', 'swordsman', 'spearman'],
  advanceRatio: 0.9,
  retreatRatio: 0.35,
};
```

```ts
/**
 * The tactical layer (spec §9.1): "what to build, whether to push".
 *
 * It produces the SAME `Command` type the player's input produces, so the AI is
 * literally pressing the player's buttons. That is what makes it fair — it has
 * no capability the player lacks — and it is why the difficulty lever is just
 * the profile's numbers rather than a separate code path.
 *
 * Pure: reads the world, returns commands, mutates nothing. The caller
 * (commandsSystem) feeds the result through the ordinary command pipeline.
 */

import { UNITS } from '../data/units';
import { canQueue } from './training';
import type { AiProfile } from './ai-profile';
import type { Command, Side, Unit, World } from './types';

/** Combat units only — miners are governed by `minerTarget`, not the posture. */
function combatUnits(world: World, side: Side): Unit[] {
  return world.units.filter(
    (u) => u.side === side && u.typeId !== 'miner' && u.state !== 'dead' && u.hp > 0,
  );
}

function minersOf(world: World, side: Side): Unit[] {
  return world.units.filter(
    (u) => u.side === side && u.typeId === 'miner' && u.state !== 'dead' && u.hp > 0,
  );
}

/**
 * How many of each combat type this side has ASKED for, so the build order can
 * keep cycling without storing an index on the world (which would need hashing).
 * Derived from what exists, so it is stateless and deterministic.
 */
function purchasedCount(world: World, side: Side, typeId: string): number {
  let n = 0;
  for (const u of world.units) {
    if (u.side === side && u.typeId === typeId && u.state !== 'dead' && u.hp > 0) n += 1;
  }
  for (const order of world.trainingQueue[side]) {
    if (order.typeId === typeId) n += 1;
  }
  return n;
}

/**
 * The next combat unit to buy: the entry in the build order that this side has
 * the FEWEST of. That yields the profile's ratio in steady state without any
 * stored cursor, and it self-corrects if units die.
 */
function nextBuildType(world: World, side: Side, profile: AiProfile): string | null {
  let best: string | null = null;
  let bestCount = Infinity;
  for (const typeId of profile.buildOrder) {
    const n = purchasedCount(world, side, typeId);
    if (n < bestCount) {
      bestCount = n;
      best = typeId;
    }
  }
  return best;
}

/** The posture this side should be in, from raw unit counts (Q8). */
function desiredStance(world: World, side: Side, profile: AiProfile): 'advance' | 'hold' | 'retreat' {
  const mine = combatUnits(world, side).length;
  const theirs = combatUnits(world, side === 'player' ? 'enemy' : 'player').length;

  // With no army at all there is nothing to posture; the caller emits nothing.
  if (mine === 0) return 'hold';
  if (theirs === 0) return 'advance';
  if (mine <= theirs * profile.retreatRatio) return 'retreat';
  if (mine >= theirs * profile.advanceRatio) return 'advance';
  return 'hold';
}

/**
 * The commands this side's tactical layer wants to issue this tick.
 *
 * Returns [] on every tick that is not a decision tick. Emitting every tick
 * would re-issue the same orders 30 times a second: the stance order would be
 * harmless but wasteful, and the train order would be checked against gold on
 * every tick for no reason.
 */
export function decideCommands(world: World, side: Side, profile: AiProfile): Command[] {
  const interval = profile.decisionIntervalTicks;
  if (interval <= 0) return [];
  if (world.tick % interval !== 0) return [];

  const commands: Command[] = [];

  // 1. Economy first: miners pay for everything else. Only queue one per
  //    decision so a windfall does not convert the whole army into miners.
  if (minersOf(world, side).length < profile.minerTarget) {
    if (canQueue(world, side, 'miner').ok) {
      commands.push({ kind: 'train', side, typeId: 'miner' });
    }
    // Deliberately returns here: while under the miner target, gold goes to
    // miners, which is what makes the opening a real ramp rather than a rush.
    return commands;
  }

  // 2. Army: one unit per decision, cycling the build order.
  const next = nextBuildType(world, side, profile);
  if (next !== null && canQueue(world, side, next as Unit['typeId']).ok) {
    commands.push({ kind: 'train', side, typeId: next as Unit['typeId'] });
  }

  // 3. Posture: address COMBAT units only. A stance order that included miners
  //    would freeze the economy — movementSystem returns early for 'hold'.
  const army = combatUnits(world, side);
  if (army.length > 0) {
    commands.push({
      kind: 'setStance',
      side,
      unitIds: army.map((u) => u.id),
      stance: desiredStance(world, side, profile),
    });
  }

  return commands;
}
```

```ts
/** A whole-match result: the outcome plus how it ended. */
export interface MatchResult {
  outcome: Outcome;
  ticks: number;
  hash: string;
  survivors: Record<Side, number>;
}

/**
 * Runs a complete level with BOTH sides driven by the tactical layer.
 *
 * `playerProfile` names the profile for the player's side: 'reference' for the
 * competent-player proxy, 'none' for a player who does nothing. This is what
 * makes "the level is winnable" a deterministic assertion rather than a claim
 * about human skill.
 */
export function runMatch(
  config: MatchConfig,
  seed: number,
  playerProfile: 'reference' | 'none',
  maxTicks: number = DEFAULT_MAX_TICKS * 2,
): MatchResult {
  const world = createWorld(config, seed);
  let ticks = 0;

  while (world.outcome === 'ongoing' && ticks < maxTicks) {
    const commands: Command[] = [];
    if (playerProfile === 'reference') {
      commands.push(...decideCommands(world, 'player', PLAYER_REFERENCE));
    }
    step(world, commands);
    ticks += 1;
  }

  return {
    outcome: world.outcome,
    ticks,
    hash: hashWorld(world),
    survivors: {
      player: world.units.filter((u) => u.side === 'player').length,
      enemy: world.units.filter((u) => u.side === 'enemy').length,
    },
  };
}
```
